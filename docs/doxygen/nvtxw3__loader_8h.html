Detailed Description

Reference loader and config utilities for the NVTX Writer API.

The functions declared here (see src/nvtxw3_loader.c) are a reference implementation for locating and loading an NVTXW backend library. They are optional: an application may instead load a backend library by any mechanism it prefers, resolve the backend's exported "nvtxwGetInterface" symbol, and request the desired nvtxwInterface_* function table. The producer/backend contract lives in nvtxw3.h.

◆ NVTXW_LIBRARY_ENV_VAR

#define NVTXW_LIBRARY_ENV_VAR   "NVTXW3_LIBRARY"

Environment variable consulted by nvtxwLoad.

When set to a non-empty value, it is treated as the backend library filename or path to load (passed verbatim to dlopen/LoadLibrary) and takes priority over both the library argument and the built-in search locations. This lets a tool or launcher redirect the backend without rebuilding the instrumented application, much like NVTX injection uses NVTX_INJECTION*_PATH. Unset or empty is ignored.

◆ nvtxwKeyValuePairConsumer_t

typedef int(* nvtxwKeyValuePairConsumer_t) (void *state, const char *keyBegin, const char *keyEnd, const char *valBegin, const char *valEnd)

Callback function pointer used with nvtxwConsumeConfigString.

The state pointer can be used for anything – nvtxwConsumeConfigString passes it directly to the callback. The begin/end pointers for the key and value are pointing to ranges within the input config string. If the input config string is known to be non-const, this callback can safely cast away const and write to these pointers, for example when simplifying an input config string. To check if a key name is a particular string, use:

keyEnd - keyBegin == strlen("ExampleKeyName") &&
strncmp("ExampleKeyName", keyBegin, keyEnd - keyBegin) == 0

In C++, you can construct a string using std::string(keyBegin, keyEnd). Return zero to continue consuming key/value pairs, or non-zero to stop.

◆ nvtxwLoad()

NVTXW_DECLSPEC nvtxwResultCode_t nvtxwLoad ( const char *  library,
nvtxwGetInterface_t *  getInterfaceFuncOut,
nvtxwModuleHandle_t *  moduleHandleOut 
)

Load an NVTXW backend library and resolve its exported entry point.

Resolving that symbol (NVTXW_GET_INTERFACE_SYMBOL_NAME) is what makes a library a usable backend. The loader does not call into the backend, so the returned function pointer is invoked by the caller (typically via nvtxwLoadInterface) to request an interface table.

Library resolution, in priority order:

  1. The NVTXW3_LIBRARY environment variable, if set to a non-empty value.
  2. The library argument, if non-NULL: a filename or path passed verbatim to dlopen/LoadLibrary (a bare filename uses the standard search paths; an absolute path is used as-is).
  3. If library is NULL: a default search for NVTXW_LIB_FILENAME_DEFAULT in the current process's executable directory, the standard dynamic library search paths, then the current working directory. When the environment variable or the library argument names a specific library, that library is the only candidate: if it fails to load or lacks the symbol, that failure is returned rather than falling back to other locations.
Parameters
libraryNULL to use the default search, or a backend filename/path.
getInterfaceFuncOutmust not be NULL. It receives a pointer to the backend's nvtxwGetInterface function, used to request interface tables.
moduleHandleOutmay be NULL. If non-null, it receives the platform-specific module handle of the loaded backend library when NVTXW_RESULT_SUCCESS is returned. This can be passed to nvtxwUnload to unload the backend library.

NVTXW_DECLSPEC void nvtxwUnload ( nvtxwModuleHandle_t  moduleHandle)

Unload a backend library previously loaded by nvtxwLoad.

If not called, the backend stays loaded until process exit. Call it only after all sessions, streams, and other backend calls have completed. If the backend exports "nvtxwFinalize" (NVTXW_FINALIZE_SYMBOL_NAME), that hook runs before the module handle is released.
